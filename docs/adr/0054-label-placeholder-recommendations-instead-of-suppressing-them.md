# Label placeholder recommendations instead of suppressing them

When the recommendation API returns nothing usable the kiosk picks an item itself so the surface does not go blank. That item is not a recommendation anyone made, which argues for withholding its `recommendation_shown` event the way an unauthored commercial touch is withheld. The two cases are not alike. A commercial touch is a leaf: dropping it removes a row and nothing else refers to it. A recommendation event is the head of a chain — the later add-to-cart, checkout, ignored and removed events resolve back to the remembered record, and they fire whether or not the item was authored. Suppressing only the first event would leave conversions attributed to a record that was never written, which is a worse reporting defect than the one it set out to fix.

Placeholder events therefore continue to report, carrying a source of `local_default` or `local_fallback` that no server-authored recommendation uses, and operational reporting excludes them by source. A blank source is excluded with them, because absence of a source is not evidence that the server chose the item. This puts the burden on every report built on these records to state its exclusion rather than on the kiosk to hide what the customer was shown, and it keeps the chain intact for the case a customer does order the placeholder item — which is real behaviour worth measuring, just not as recommendation performance.
