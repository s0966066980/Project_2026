# Require confirmation before publishing diagnostic RAG changes

Status: accepted

A Daily Diagnostic Question may produce a reviewable Knowledge Change Candidate only when the finding is classified as an RAG Knowledge Gap under ADR-0043, has repeated or reproducible evidence under ADR-0044, and passes the offline acceptance required by ADR-0051. Reports that do not meet all three conditions remain readable but expose no RAG publication action. The analyzer still has no production-write authority: the candidate must show the proposed knowledge fields and supporting evidence, and only an explicit administrator confirmation may send it through the existing Knowledge Item save flow, where save automatically starts indexing and publication. An administrator may edit the candidate, but every edit invalidates its acceptance result and keeps confirmation disabled until the edited candidate passes a new offline evaluation. A candidate that revises existing knowledge carries the compared row revision; a conflicting later edit makes it stale and forces regeneration instead of overwrite or automatic merge. Each store has at most one pending candidate, and another diagnosis may start only after the administrator explicitly abandons it; no candidate is silently replaced or accumulated into a queue.

This partially supersedes ADR-0041. Daily optimization remains unable to mutate prompts, models, settings, campaigns, recommendations, or project files, but its Admin surface may now apply one confirmed RAG knowledge creation or revision when the administrator has both `rag.write` and `rag.publish`. ADR-0047's service boundary remains: the Optimization Lab never calls the RAG publication interface itself; an authenticated application workflow performs the confirmed write.
