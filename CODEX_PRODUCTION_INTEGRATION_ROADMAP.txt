MILESTONE 5A
Worker / Outbox Correctness
======================================================================

優先級：P0

目標：

修正 Worker 假成功與 Outbox 假發布。
任何工作只有真正 Handler 成功後才能 Success。
任何 Outbox 只有真正 Sink ACK 後才能 Published。

Current Risk：

目前 PostgreSQL Worker 可能：

claim job
→ 不執行 Handler
→ complete

以及：

claim outbox
→ 不送 Sink
→ mark published

這會造成資料與事件遺失。

必做：

1. Handler Registry

建立統一：

JobHandlerRegistry

能力：

register(job_type, handler)
resolve(job_type)
validate_required_handlers()
list_registered()

Production：

- 未註冊 Handler 不得 Success。
- 未註冊 Handler 應記 safe error、metric，依明確 Policy 進 Retry 或 DLQ。
- Test 可使用 Fake Handler。

2. PostgreSQL Worker 使用真正 Handler

run_worker.py 不得自行建立：

JobHandlerResult(success=True)

改為：

claim
→ deserialize job
→ resolve handler
→ execute
→ validate result
→ complete / fail / dead-letter

3. Handler Result Contract

回傳：

success
retryable
safe_error
result_ref
side_effect_id

不得回傳 Secret/PII。

4. Required Handler Inventory

盤點 ALLOWED_JOB_TYPES。

至少分類：

rag.rebuild
report.generate
ai.background
data.export
retention.cleanup
analytics.publish
notification.send
其他實際 Type

每個 Type 必須：

- 有真正 Handler；或
- 明確 Unsupported Handler；
- 不可 No-op Success。

5. Outbox Delivery Router

建立：

OutboxDeliveryRouter

依 event_type：

order_confirmed
order_completed
order_cancelled
其他實際 Type

路由：

analytics sink
POS sink
notification sink
internal sink

只有 Sink ACK 才可：

mark_outbox_published

6. Delivery Result

包含：

success
retryable
safe_error
delivery_id
provider
acknowledged_at

7. Durable Idempotency

Sink 以 event_id 唯一。

同 event_id 重送：

不重複 side effect
→ 回已處理 ACK

8. Crash Recovery

測：

- Handler 執行前 Crash。
- Side-effect 後、Ack 前 Crash。
- Visibility Timeout。
- Reclaim。
- Duplicate Delivery。

9. Dead Letter

需保存：

reason
attempt_count
last_error
dead_lettered_at

Admin/Operations 可讀，不得含 PII。

10. Metrics

worker_job_started
worker_job_succeeded
worker_job_failed
worker_job_retry
worker_job_dlq
worker_unknown_handler
outbox_delivery_attempt
outbox_delivery_success
outbox_delivery_retry
outbox_delivery_dlq
outbox_oldest_age

11. PostgreSQL Integration

使用真實 PostgreSQL：

- enqueue job。
- Worker process 執行。
- 驗證 side effect。
- 驗證 row status。
- 重跑 idempotent。
- Handler exception。
- Retry。
- DLQ。

Outbox：

- insert order/outbox。
- Sink 第一次 fail。
- 不可 Published。
- 第二次 success。
- 才 Published。
- 重跑不重複。

12. CI

新增或整合：

postgres_worker_production_path_integration.py

Gate：

PRODUCTION_PATH_PASS：

- No no-op success。
- Unknown handler 不成功。
- PostgreSQL Worker 真執行 Handler。
- Sink ACK 前不 Published。
- Crash recovery PASS。
- Duplicate delivery PASS。
- Retry/DLQ PASS。
- Full Regression PASS。

Non-goals：

- 真實 Payment Provider。
- 真實 Cloud Analytics。
- 大型 Worker Framework 替換。
- Kafka。

Checkpoint Commit：

fix: execute real worker handlers and acknowledge outbox delivery

8. Stop / Continue 規則
======================================================================

必須停止：

- 破壞性資料操作無安全 Roll-forward。
- Migration 遇到無法推斷的真實 Production 衝突。
- 缺少 Merchant Credential、Cloud Account、TLS/Domain、Legal/Privacy Approval，
  且沒有安全替代。
- 真實 Security Risk 無法安全處理。
- 使用者未提交修改與 Roadmap 直接衝突。

不應停止：

- Test fail。
- Lint fail。
- Type fail。
- Dependency conflict。
- CI fail。
- Docker local unavailable。
- Redis local unavailable。
- Provider unavailable但可用 Test Adapter。
- Push unavailable。
- 命名可合理推斷。
- Module placement 可從 AGENTS 推斷。

遇到 External Block：

- 完成 Contract。
- 完成 Fake/Test Adapter。
- 完成 Integration Harness。
- 記錄 Required External Input。
- 繼續不依賴該外部項目的 Milestone。
