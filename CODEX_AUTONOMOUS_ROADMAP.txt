======================================================================
1. 不可破壞的專案邊界
======================================================================

Project_2026 是智慧自助點餐、會員、推薦、語音、情緒證據與客服介入系統。

核心閉環：

POS interaction event
  → risk_score
  → 短多模態片段
  → evidence
  → barrier_state_service
  → intervention_service
  → WebSocket / Kiosk UI
  → checkout / outcome writeback

硬性限制：

1. Emotion-LLaMA、R1-Omni 是模型執行單元與證據來源，不是核心決策中心。
2. 最終介入決策保留 risk → evidence → barrier state → intervention。
3. 模型不得直接寫入核心交易資料，也不得阻塞 Checkout。
4. 不得破壞：
   /kiosk、/admin、既有 /api/*、WebSocket、會員、推薦、RAG、語音、
   情緒流程、8000/8001 隔離、Menu whitelist 與既有商品 ID contract。
5. 保持 Modular Monolith First。
6. 依賴方向：
   Route/API → Application Service → Domain Policy → Repository Port → Adapter。
7. Route 不放複雜商業邏輯。
8. Service 不直接讀寫 JSON，不依賴 FastAPI Request/Response。
9. Repository 不 import Service 或 Route。
10. 外部 AI、STT、TTS、Storage、Notification、Realtime 逐步用 Port/Adapter 隔離。
11. 已套用 Migration 不得修改、刪除、重新編號或繞過 Checksum。
12. 不提交 Secret、Token、Password、Private Key、模型權重、真實會員資料或 Production Dump。
13. PII Log 預設遮罩；Phone 不作為長期公開 Domain ID。
14. 不使用裸 except 或 except Exception: pass 隱藏 Production 錯誤。
15. 不以刪除測試、停用功能、大量 noqa/type:ignore 讓 CI 通過。
16. 保留使用者現有修改。
17. 禁止 git reset --hard、force push、改寫共享歷史。
18. 禁止無關搬移、大量格式化、Big Bang Rewrite。
19. 禁止未經 ADR 拆成大量 Microservices。
20. 不在沒有 Adapter 必要性時修改 Emotion-LLaMA 或 R1-Omni 核心模型。

2. Autonomous Execution Protocol
======================================================================

A. 每次開始或恢復

先讀：
- AGENTS.md
- 距離目標檔案最近的 AGENTS.md
- README.md
- docs/ARCHITECTURE.md
- docs/COMMERCIAL_GOVERNANCE.md
- docs/FUTURE_MODULES.md
- docs/POSTGRESQL_MIGRATIONS.md
- docs/adr/README.md
- CODEX_AUTONOMOUS_ROADMAP.txt
- .github/workflows/ci.yml

執行：

git status --short
git branch --show-current
git log --oneline -20

規則：
- 不覆蓋未提交的使用者修改。
- 不使用 reset、checkout -- 或 clean 刪除使用者工作。
- 若在 main/master，建立長期 Branch：
  codex/project-2026-commercialization-roadmap
- 若已在 codex/*，延續目前 Branch。
- 不必每個 Milestone 重新開 Branch。
- 每個 Milestone 建立獨立 Checkpoint Commit。

B. 狀態檔

建立並維護：

.codex/project_2026_execution_state.json

初始格式：

{
  "plan_version": "2026-07-13",
  "repository": "s0966066980/Project_2026",
  "base_head": "c6ffac8a9dcb1e37d1685dd252a146d76fc165f5",
  "current_milestone": "1B.1",
  "status": "not_started",
  "completed_milestones": [],
  "checkpoint_commits": {},
  "verification": {},
  "known_gaps": [],
  "blocked_items": [],
  "next_milestone": "1C",
  "updated_at": ""
}

status 允許：
not_started、in_progress、verification_failed、blocked、passed、complete。

狀態檔不得包含 Secret、Token、Password、DATABASE_URL、PII、真實會員資料。

C. 每個 Milestone 固定流程

1. Discover
   - 讀目標入口、直接 callers、service、repository、schema、tests。
   - 搜尋既有實作，避免重複 Module。
   - 局部任務不重新完整稽核整個 Repository。

2. Plan
   - 列出 Scope、Affected modules、Compatibility、Security boundary、
     Migration/Roll-forward、Test strategy。
   - 只有跨模組、安全、Database、Deployment 才需要完整計畫。

3. RED
   - 先建立失敗測試或明確驗收。
   - 建立 .github/tdd/<milestone>.tdd.md。
   - 記錄真實 RED，不偽造。

4. GREEN
   - 實作最小可用範圍。
   - 不順便重構無關模組。
   - 保持 Compatibility Adapter。

5. Harden
   - 補 Boundary、Error handling、Security、Concurrency、Idempotency、
     Data preservation、Observability、Failure recovery。

6. Verify
   - Target Tests。
   - 受影響 Integration。
   - Full JSON Backend。
   - Static Check。
   - Frontend/Shell（受影響時）。
   - 未執行標示 NOT RUN，絕不可描述為 PASS。

7. Document
   依影響更新：
   README、docs/ARCHITECTURE.md、docs/FUTURE_MODULES.md、
   docs/POSTGRESQL_MIGRATIONS.md、ADR、Runbook。
   只有重大且長期架構決策建立 ADR。

8. Commit
   - git diff --check
   - git status --short
   - Commit 只包含單一 Milestone。
   - 不含 runtime data、cache、模型、dump、無關格式化。

9. Continue
   - Gate PASS → 更新 State → Checkpoint Commit → 自動進入下一 Milestone。
   - 可 Push 則 Push 到目前 codex/* Branch。
   - Push 不可用記錄 NOT PUSHED，但不阻斷後續本機工作。

D. 自主決策優先順序

安全與資料正確性
→ Backward Compatibility
→ Modular Monolith
→ Typed Contract
→ Server-side Enforcement
→ PostgreSQL 為正式商業資料 Source of Truth
→ Production Fail Closed
→ 可測試、可觀測、可 Roll-forward
→ 最小改動
→ 不提前最佳化

有合理預設時直接執行，不反覆詢問。

新增 Dependency 時：
- 只在對應 Milestone 內新增。
- 使用維護中、用途單一的套件。
- 鎖定版本並更新 lockfile。
- 文件化原因與替代方案。
- 不為小功能引入大型 Framework。

真正阻斷時：
- 完成所有不依賴阻斷的工作。
- 在 blocked_items 記錄 blocker、impact、required external input。
- 不偽造外部服務成功。
- 不把未驗證功能標示 PASS。

- Audit 跨 Tenant/Store collision。
- Event 跨 Tenant/Store/Device collision。
- Session origin device immutable。
- Production read/write 不 fallback JSON。

- Readiness missing/inactive/mismatch。

======================================================================
停止條件
======================================================================

只有以下情況停止自動延續：

1. 破壞性資料操作沒有安全 Roll-forward。
2. Migration 發現無法推斷的真實 Production 資料衝突。
3. 缺少且無安全替代的：
   Production Secret、Payment Merchant Credential、Cloud Account、
   Domain/TLS Control、法務/隱私核准。
4. 現有使用者修改與 Roadmap 直接衝突。
5. 測試揭露核心架構事實與 Roadmap 假設相反，
